Archivos que llegan en Latin-1 con separadores ";" desde SAP, con headers en la fila 3 y columnas "Unnamed". AEGIS detecta automáticamente encoding, delimitador y fila de encabezado.

💰
Montos escritos de 20 formas distintas

"$3.240.000", "3240000", "tres mil dólares", "500 lucas", "US$ 1,200.50". El motor monetario de AEGIS normaliza todos estos formatos a números reales con moneda detectada.

🔑
IDs transaccionales destruidos por Excel

Excel convierte "TRX-0052" en -52 y "001234" en 1234. AEGIS detecta columnas ID con patrón regex, restaura prefijos (TRX-XXXX) y preserva la trazabilidad original.

📅
Fechas ambiguas en 5 formatos distintos

03/04/2024: ¿marzo o abril? AEGIS usa dayfirst=True con format=mixed, detecta formatos ISO (YYYY-MM-DD) vs locales, y nunca inventa fechas faltantes — solo las marca para auditoría.

Pipeline real

7 fases automáticas.
Zero configuración manual.

Cada fase tiene umbrales matemáticamente justificados. Umbral de conversión: 85% (test binomial H₀:p≤0.5, z=4.95, p-value<10⁻⁶).

01
Detección
FileDetector + DataLoader

Detecta tipo de archivo (CSV/Excel), prueba 4 encodings (UTF-8, UTF-8-BOM, Latin-1, ISO-8859-1), detecta delimitador con csv.Sniffer, y localiza la fila de encabezado real con scoring heurístico.

02
Limpieza
DataCleaner configurable

Normaliza columnas, detecta IDs con regex (^id_|_id$|^codigo|trx|folio), restaura prefijos TRX-, limpia monetarios, estandariza fechas, elimina duplicados y columnas >90% nulas.

03
Modelado
OLAP Cube Builder

Genera automáticamente dimensiones (fecha, geografía, producto, cliente), tabla de hechos con medidas tipadas (SUM/AVG/LASTNONEMPTY), jerarquías validadas por cardinalidad, y particiones por año.

Fase 0 FileDetector.detect_and_validate() → csv | excel
Fase 1 DataLoader.load_csv() → auto-encoding, sniffer, header detection
Fase 2 DataCleaner.clean_columns() → IDs, montos, fechas, estados
Fase 3 ColumnProfiler → semantic_type, role, cardinality, candidate_keys
Fase 4 CubeSpec → dimensions[], fact{measures[], partitions[]}
Fase 5 ExtractionEngine → ParquetWriter (ZSTD, checkpointing)
Fase 6 SSAS/XMLA export → deploy_ssas.ps1 → Analysis Services
Capacidades reales

Cada módulo resuelve un
problema concreto.

No es una demo. Son componentes de producción extraídos directamente del motor AEGIS.

🔄
Motor monetario inteligente

Parsea "$3.240.000", "3 mil dólares", "500 lucas", "US$ 1,200.50". Detecta moneda (CLP/USD/EUR), convierte con tipo de cambio (MockFXProvider: 1 USD = $900 CLP), y preserva el valor original para auditoría.

🛡️
Restauración de IDs

Regex pattern: (^id_|_id$|^codigo|trx|folio|transaccion). Detecta IDs destruidos por Excel (ej: -4471), restaura a formato TRX-4471, preserva columna _original para trazabilidad completa.

📊
OLAP automático

Genera CubeSpec completo: dim_date (day→month→quarter→year), dim_geography (tienda→ciudad→región→país), dim_product, dim_customer. Medidas con additivity correcta (SUM, AVG, LASTNONEMPTY).

⚡
Extracción paralela

ThreadPoolExecutor con backpressure, detección de PK vía sys.indexes, estrategias pk_range y offset_fetch, retry con backoff exponencial (RetryPolicy), y checkpointing SQLite WAL para crash-recovery.

🏷️
Normalización de estados

Catálogo de negocio: vendido→VENDIDO, pendiente→PENDIENTE, devuelto→DEVUELTO. Clasificación automática de movimientos: VENTA, DEVOLUCION, REEMBOLSO, AJUSTE, CAMBIO según monto y estado.

✅
Quality Score por fila

Score 0-100 basado en: campos críticos faltantes (-20), estado desconocido (-10), flags de calidad (-10), cuarentena (-20). Cada transformación queda registrada en data_quality_flag con trazabilidad completa.

Casos de uso reales

Diseñado para quien
pelea con datos.

AEGIS fue construido resolviendo problemas reales con archivos reales de ERPs chilenos.

Finanzas / Contabilidad
"Recibimos facturas de 20 proveedores con montos en CLP, USD y EUR — todos en formatos distintos"
AEGIS: El motor clean_monetary_string() detecta la moneda, normaliza a float, aplica tipo de cambio FX y genera columnas monto_clp_normalizado + moneda_detectada + fx_rate.
Data Engineering
"Necesito extraer 50M de filas de SQL Server a Parquet sin que se caiga el proceso"
AEGIS: ExtractionEngine con chunks de 100K filas, compresión ZSTD nivel 3, checkpointing SQLite WAL, y resume automático desde el último chunk completado.
Business Intelligence
"Paso semanas modelando cubos OLAP para Analysis Services desde CSVs sucios"
AEGIS: De CSV a CubeSpec con dimensiones, jerarquías validadas, medidas tipadas y exportación XMLA — automáticamente. Deploy directo a SSAS con deploy_ssas.ps1.
Operaciones / Logística
"Los IDs de transacción llegan como -52 porque Excel destruyó el formato TRX-0052"
AEGIS: restore_id_prefix() detecta IDs negativos, extrae dígitos con regex, regenera TRX-0052, y preserva el valor original en columna _original para auditoría.
Auditoría / Control
"No sé cuáles datos fueron modificados durante la limpieza ni cuáles filas son confiables"
AEGIS: data_quality_flag registra cada transformación (|id_prefix_restored|amount_imputed_to_0.0). quality_score califica cada fila de 0 a 100. Nada se inventa, todo se traza.
Análisis de datos
"Tengo Excel con headers en la fila 5, columnas Unnamed y mezclados con texto libre"
AEGIS: _detect_header_row() usa scoring heurístico (string ratio, numeric next row, null ratio). Elimina columnas >90% nulas y "Unnamed". El resultado es un DataFrame limpio listo para pandas.
